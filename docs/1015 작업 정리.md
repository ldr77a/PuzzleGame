## 3. 스테이지 6\~13번

| 스테이지 | 쓰는 3색 | 목표 | 문 |
|---|---|---|---|
| 6 벽 | 빨강, 연두, 파랑 | 빨강 1 + 연두 2 | |
| 7 갈림길 | 주황, 파랑, 남색 | 주황 2 + 남색 1 | |
| 8 네 방울 | 노랑, 파랑, 보라 | 노랑 2 + 파랑 1 + 보라 1 | |
| 9 막다른 길 | 빨강, 연두, 보라 | 연두 2 + 보라 2 | |
| 10 동백꽃 문 | 주황, 파랑, 보라 | 파랑 1 + 보라 1 | 주황 + 보라 |
| 11 초록 문 | 노랑, 파랑, 남색 | 노랑 2 + 남색 1 | 노랑 + 파랑 |
| 12 청록 문 (전: 연두 문) | 연두, 파랑, 보라 | 연두 1 + 보라 1 | 연두 1 + 파랑 2 |
| 13 구석 정원 | 주황, 남색, 보라 | 주황 1 + 남색 2 | 주황 1 + 보라 2 |

- 판 모양, 벽과 문 위치, 최단 걸음은 그대로입니다. 판마다 최단 정답은 한 가지입니다.
- `lab.sh check`에 **헷갈림 검사**를 넣었습니다. 같은 방울 수로 그 판의 색만 써서 만들 수 있는 다른 레시피가 목표색(또는 문 색)과 ΔE 10 안이면 실패입니다. 바꾸기 전에는 12번과 13번의 문이 이 검사에서 떨어졌습니다(ΔE 8.7).

**리뷰에서 찾아 고친 문제**

| 문제 | 수정 |
|---|---|
| 힌트 0개일 때 무료 안내("빛나는 칸으로 가 보세요", 막힘 안내) 대신 받기 창이 먼저 뜸 | 무료 안내를 먼저 확인하고, 받기 창은 다음 한 걸음을 줄 수 있을 때만 |
| 클리어 직후 0.3초 사이에 메뉴를 열면 꽃 피는 연출이 메뉴 뒤에 가려짐 | 클리어한 뒤에는 메뉴와 뒤로 버튼을 무시 |
| 폰에서 정원 꽃을 누를 때 손가락이 조금만 움직여도 스크롤로 인식됨 | 화면 밀도에 맞춰 끌기 기준을 넓힘 |
| 두 번 탭하면 두 번째 탭이 "다음", 정원의 꽃, 판까지 누름 | 화면이 바뀐 직후 0.25초는 탭을 받지 않음 |
| iPad처럼 넓은 화면에서 판이 너무 작음 | 화면 비율에 따라 UI 크기 기준을 바꿈 (iPad 판 너비 46% → 57%) |
| 정원으로 돌아올 때 스크롤이 한 번 튐 | 화면을 열 때 바로 지금 스테이지로 스크롤 |
| 색이 많은 레시피 칩이 옆으로 넘침 | 두 줄로 나누고 크기를 맞춤 |
| Android 뒤로 버튼으로 타이틀에서 나갈 수 없음 | 타이틀에서 뒤로 = 앱 종료 |
| 플레이테스트 창 문구가 새 화면 흐름과 다름, 가짜 굵게 | 문구 수정 ("정원에서 시작", 힌트도 초기화), 굵게 제거 |
| 효과음 출력 장치(AudioListener)를 한 번만 확인 | 씬이 바뀔 때마다 확인 |
| 진동 권한이 빌드에서 빠질 수 있음 | 빠지지 않게 표시 |
| 스테이지 파일의 `focus`가 벽이나 시작 칸이어도 통과 | 거부하고 테스트 추가 |
| 힌트 계산의 경계 상황 테스트 부족 | 테스트 6개 추가 |
| 카멜리 볏 외곽선이 그림 가장자리에서 잘림 | 크기 조정 |

- 화면은 아직 Unity에서 실행해 보지 않았습니다.
