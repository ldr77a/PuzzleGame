## 2. 작업 6: 플레이테스트 준비

### 2.1 게임 안 플레이테스트 도구 (`Assets/Scripts/Cameli/Game/`)

| 파일 | 내용 |
|---|---|
| `LongPress.cs` | 2초 길게 누르기 감지 |
| `PlaytestPanel.cs` | 스테이지 이름을 길게 누르면 뜨는 창. "다음 테스터"(두 번 눌러야 실행), "기록 보기", "닫기" |
| `PlaytestLog.cs` | 스테이지 시도마다 기기의 `playtest.csv`에 한 줄씩 기록. 테스터별 요약(클리어 수, 튜토리얼 통과, 되돌리기, 재시작, 시간) |
| `Progress.cs` | 진행 초기화 `ResetAll` 추가 |
| `CameliGame.cs`, `HudView.cs` | 위 기능 연결. 플레이테스트 중 화면이 꺼지지 않게 함 |

- **기록 규칙**
  - 시도는 스테이지에 들어갈 때 시작합니다. 클리어하면 다시 하기로 새 시도가 시작됩니다.
  - 시도는 클리어, 다른 스테이지로 이동, "다음 테스터", 앱이 백그라운드로 감, 앱 종료 중 하나로 끝납니다.
  - 아무것도 하지 않고 끝난 시도는 기록하지 않습니다.
- **테스터 번호**
  - "다음 테스터"를 누르면 1 올라갑니다. 지금 테스터의 기록이 없으면 그대로입니다.
  - 번호는 진행을 초기화해도 유지되고, 앱을 다시 설치하면 초기화됩니다.
- 지시문 6은 "확인 창"을 요구했지만, "다음 테스터"를 두 번 누르는 방식으로 바꿨습니다. 첫 번째로 누른 뒤 "닫기"를 누르면 아무 일도 일어나지 않습니다.

### 2.2 플레이테스트 기록지

[`플레이테스트 기록지.md`](플레이테스트%20기록지.md)를 서브에이전트가 작성했고, 리뷰를 거쳐 코드와 맞췄습니다.
- 준비 체크리스트, 앱 안 도구 사용법, 진행 대본
- 사람별 기록표(스테이지 1\~13), 끝난 뒤 질문
- 합격 판정표: 13스테이지 기준 평균 9개 이상 클리어로 환산
- 에이전트에게 넘기는 법

### 2.3 리뷰에서 찾아 고친 문제

| 문제 | 수정 |
|---|---|
| 휴대폰은 백그라운드 앱을 종료할 때 종료 콜백을 부르지 않아서, 그 판이 기록에서 빠짐 | 앱이 백그라운드로 갈 때 `pause`로 기록하고, 돌아오면 이어서 기록 |
| 첫 테스터 전에 "다음 테스터"를 누르면 가짜 테스터 1이 생기고, 실제 첫 사람이 2번이 됨 | 빈 시도는 기록하지 않고, 기록이 없는 테스터는 번호를 올리지 않음 |
| 클리어하는 걸음의 애니메이션(0.12초) 도중 백그라운드로 가면 클리어 기록이 빠짐 | 일시정지할 때 애니메이션을 먼저 끝내서 클리어를 기록 |
| 기록지 설명이 코드와 다른 곳 (요약은 합계만 나옴, 클리어 창이 제목을 가림, iPhone은 CSV를 못 꺼냄 등) | 기록지 수정 |
