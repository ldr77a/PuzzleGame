## 2-1. 카멜리 움직임과 표정

| 질문 | 결정 |
|---|---|
| 움직임 | 그림 한 장 + 코드 움직임. 칸마다 통통 뛰고 꼬리가 살랑 |
| 명암 | 없이 선만 |
| 표정 | 기본, 기쁨(깸), 놀람(넘침, 부딪힘) |
| 보는 방향 | 옆모습 하나, 좌우 뒤집기 |

- 임시 카멜리에 바로 넣었습니다: 판 위에서 칸마다 통통 뛰고(공중에서 늘어나고 내려앉을 때 찌그러짐), 꼬리가 살랑이고, 깨면 눈을 "^"로 감고, 넘치거나 부딪히면 눈이 커집니다.
- 표정은 판 위의 카멜리에만 나옵니다(목표 카드의 카멜리는 아래 2-2에서 뺐습니다).
- 도트 그림으로 바뀌어도 쓸 수 있게 찌그러짐과 꼬리 흔들기는 숫자 하나로 끌 수 있습니다.
- 기획서 8.1, 13절과 화면 명세 16절에 반영했습니다.
- 검증: 코어 58/58, 컴파일 OK ×3, 스테이지 49개 OK. 화면은 아직 Unity에서 실행해 보지 않았습니다.

## 2-2. 목표 카드 다듬기와 유사도

| 질문 | 결정 |
|---|---|
| 이름표 "피울 꽃", "카멜리" | 뺌 |
| 오른쪽 카멜리 | 뺌 (지금 색은 판 위 카멜리로) |
| 봉오리, 방울 자리 | 세로 가운데. 방울 6개부터 두 줄 |
| "방울 2/5" | "방울" 글자만 빼고 "2/5" 남김 |
| 유사도 | 오른쪽에 숫자 %만, Hard에서도 보여 줌 |

- 유사도 계산(`ColorMath.Similarity`)을 규칙 코어에 넣고 테스트 2개를 더했습니다. 같은 색이면 100%, 색 차이 ΔE 10이면 약 75%입니다.
- 색 차이 계산(ΔE)은 스테이지 검사 도구에 있던 것을 규칙 코어로 옮겨 함께 씁니다. 검사 결과는 그대로입니다.
- 기획서 3.5, 5, 11절과 화면 명세 2, 16, 17절에 반영했습니다.

## 2-3. 그림체와 튜토리얼 결정

| 질문 | 결정 |
|---|---|
| 카멜리 그림체 | 매끈한 그림. 도트는 검토 후 취소 |
| 2\~4번 판 안내 | 판마다 맞춤: 2번, 4번은 갈 칸이 차례로 빛남, 3번은 방울 수가 반짝 |
| 다시 하기 알려 주기 | 튜토리얼에서 못 깨게 되면 [다시 하기]가 반짝이고 안내 |
| 힌트 버튼 | 튜토리얼에서는 숨김. 6번부터 보이고, 처음 막혔을 때 한 번 소개 |

- 기획서 3.4, 3.6, 5, 8.1, 13절과 화면 명세 7, 16, 18절에 적었습니다.
- 게임에 넣었습니다.
  - 스테이지 파일에 `path`(갈 방향을 차례로, 예: `"left up"`)와 `highlight`(`"count"`)를 더했습니다. 2번은 `"left up"`, 4번은 `"up down left"`, 3번은 `"count"`입니다.
  - 스테이지 검사가 `path`를 따라가 보고, 마지막 걸음에서 정확히 깨지지 않으면 문제로 알립니다. 수정 방법 문서에도 적었습니다.
  - 튜토리얼에서 못 깨게 되면 안내와 [다시 하기] 반짝임, 튜토리얼에서 힌트 버튼 숨김, 처음 막혔을 때 힌트 소개(기기마다 한 번, "다음 테스터"가 지움)
- 검증: 코어 69/69, 컴파일 OK ×3, 스테이지 49개 OK. 리뷰 에이전트가 2, 3, 5번과 일반 스테이지의 흐름을 코드로 따라가 확인했고 문제는 없었습니다. 태블릿에서 힌트 버튼 반짝임이 옆 버튼에 닿을 수 있어 반짝이는 크기를 줄였습니다. 화면은 아직 Unity에서 실행해 보지 않았습니다.
