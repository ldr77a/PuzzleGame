## 1. 고친 것

| 문제 | 수정 |
|---|---|
| 7번 스테이지 안내가 "짙은 회색 칸은 벽이에요"로 남아 있음 (벽이 울타리로 바뀌었는데) | "나무 울타리는 벽이에요. 지나갈 수 없어요." |
| 울타리에서 가로대가 판자 옆 테두리를 덮어, 가로대와 판자가 선 없이 맞닿음 | 가로대 위에 판자 테두리 층을 하나 더 그림. 바깥 테두리의 절반 두께라 판자 사이 틈으로 가로대가 계속 보임 |
| 밤에 힌트를 다 쓰고 다음 날 앱으로 돌아오면 버튼이 아직 [광고 보고 힌트]로 보임 (누르면 무료 힌트가 제대로 쓰이긴 함) | 앱으로 돌아올 때 화면 글자를 다시 읽음 |

화면 명세 14, 15절에 반영했습니다.

- Unity에서 보신 뒤: 힌트로 칸이 깜빡이는 속도가 너무 빨라서 1초에 1.6번 → 약 1.7초에 한 번으로 늦췄습니다.

## 2-1. 카멜리 움직임과 표정

| 질문 | 결정 |
|---|---|
| 움직임 | 그림 한 장 + 코드 움직임. 칸마다 통통 뛰고 꼬리가 살랑 |
| 명암 | 없이 선만 |
| 표정 | 기본, 기쁨(깸), 놀람(넘침, 부딪힘) |
| 보는 방향 | 옆모습 하나, 좌우 뒤집기 |

- 임시 카멜리에 바로 넣었습니다: 판 위에서 칸마다 통통 뛰고(공중에서 늘어나고 내려앉을 때 찌그러짐), 꼬리가 살랑이고, 깨면 눈을 "^"로 감고, 넘치거나 부딪히면 눈이 커집니다.
- 표정은 판 위의 카멜리에만 나옵니다(목표 카드의 카멜리는 아래 2-2에서 뺐습니다).
- 도트 그림으로 바뀌어도 쓸 수 있게 찌그러짐과 꼬리 흔들기는 숫자 하나로 끌 수 있습니다.
- 기획서 8.1, 13절과 화면 명세 16절에 반영했습니다.
- 검증: 코어 58/58, 컴파일 OK ×3, 스테이지 49개 OK. 화면은 아직 Unity에서 실행해 보지 않았습니다.

## 2-2. 목표 카드 다듬기와 유사도

| 질문 | 결정 |
|---|---|
| 이름표 "피울 꽃", "카멜리" | 뺌 |
| 오른쪽 카멜리 | 뺌 (지금 색은 판 위 카멜리로) |
| 봉오리, 방울 자리 | 세로 가운데. 방울 6개부터 두 줄 |
| "방울 2/5" | "방울" 글자만 빼고 "2/5" 남김 |
| 유사도 | 오른쪽에 숫자 %만, Hard에서도 보여 줌 |

- 유사도 계산(`ColorMath.Similarity`)을 규칙 코어에 넣고 테스트 2개를 더했습니다. 같은 색이면 100%, 색 차이 ΔE 10이면 약 75%입니다.
- 색 차이 계산(ΔE)은 스테이지 검사 도구에 있던 것을 규칙 코어로 옮겨 함께 씁니다. 검사 결과는 그대로입니다.
- 기획서 3.5, 5, 11절과 화면 명세 2, 16, 17절에 반영했습니다.

## 2-3. 그림체와 튜토리얼 결정

| 질문 | 결정 |
|---|---|
| 카멜리 그림체 | 매끈한 그림. 도트는 검토 후 취소 |
| 2\~4번 판 안내 | 판마다 맞춤: 2번, 4번은 갈 칸이 차례로 빛남, 3번은 방울 수가 반짝 |
| 다시 하기 알려 주기 | 튜토리얼에서 못 깨게 되면 [다시 하기]가 반짝이고 안내 |
| 힌트 버튼 | 튜토리얼에서는 숨김. 6번부터 보이고, 처음 막혔을 때 한 번 소개 |

- 기획서 3.4, 3.6, 5, 8.1, 13절과 화면 명세 7, 16, 18절에 적었습니다.
- 게임에 넣었습니다.
  - 스테이지 파일에 `path`(갈 방향을 차례로, 예: `"left up"`)와 `highlight`(`"count"`)를 더했습니다. 2번은 `"left up"`, 4번은 `"up down left"`, 3번은 `"count"`입니다.
  - 스테이지 검사가 `path`를 따라가 보고, 마지막 걸음에서 정확히 깨지지 않으면 문제로 알립니다. 수정 방법 문서에도 적었습니다.
  - 튜토리얼에서 못 깨게 되면 안내와 [다시 하기] 반짝임, 튜토리얼에서 힌트 버튼 숨김, 처음 막혔을 때 힌트 소개(기기마다 한 번, "다음 테스터"가 지움)
- 검증: 코어 69/69, 컴파일 OK ×3, 스테이지 49개 OK. 리뷰 에이전트가 2, 3, 5번과 일반 스테이지의 흐름을 코드로 따라가 확인했고 문제는 없었습니다. 태블릿에서 힌트 버튼 반짝임이 옆 버튼에 닿을 수 있어 반짝이는 크기를 줄였습니다. 화면은 아직 Unity에서 실행해 보지 않았습니다.

- 지금 카멜리가 물고기 같다는 의견으로 시작해, 보내 주신 카멜레온 그림과 섞었습니다.
- 정한 모습: 머리와 몸이 나뉜 통통한 몸, 낮은 투구, 흰 눈과 눈 위의 얇은 선, 웃는 입, 반달 발, 통통하고 엉덩이에서 선 없이 이어져 아래로 크게 말린 꼬리. 점 무늬는 없음
- 게임에 넣었습니다. 그림을 레이어 PNG 7장(몸 실루엣, 꼬리 채움, 꼬리 선, 몸 채움, 얼굴 3장)으로 뽑아 `Assets/Resources/CameliArt/`에 두고, `CameliFigure`가 겹쳐 그립니다. 통통 뛰기, 표정, 꼬리 흔들기, 몸 색은 그대로입니다.
- 그림을 뽑는 도구는 `Tools/CameliArt/`(모양은 `cameli.html`, 뽑기는 `render.sh`)에 두었습니다. 나중에 직접 그린 그림도 같은 PNG 7장으로 바꾸면 됩니다.

## 2-5. 앱 아이콘, 시작 화면, 타이틀 글자, 클리어 꽃잎

시안 페이지(https://claude.ai/artifact/JZP8Rx5aEmC8CXeox8rBRd) Q1\~Q6를 모두 추천안으로 정했습니다. 자세한 내용은 화면 명세 20절에 있습니다.

- **앱 아이콘:** 처음 그린 5번(둘레에 꽃을 고르게 두른 안)이 별로라는 의견이 있었습니다. 그래서 시작 화면처럼 크기와 기울기가 제각각인 꽃을 흩고 잎을 더해 다시 그렸고, 배경은 연두로 바꿨습니다.
  - 꽃은 여러 색, 배경은 중간 연두로 정했습니다. 흰 카멜리는 정확히 한가운데에 있습니다.
  - `Tools/CameliArt/icon.html`이 게임과 같은 카멜리 그림으로 그리고, `render.sh`가 `Assets/CameliIcon/`에 iOS 한 장과 Android 적응형 아이콘(배경, 앞 그림)을 뽑습니다.
  - 카멜리 모양은 `cameli.js`로 옮겨 레이어와 아이콘이 함께 씁니다. 다시 뽑은 레이어 PNG 7장은 전과 똑같습니다.
- **시작 화면:** "Cameli → 모바일 프로젝트 설정 적용"이 Unity 로고를 끄고, 켜질 때 바탕(iOS 시작 화면 포함)을 타이틀과 같은 연한 색으로 하고, 아이콘을 프로젝트 설정에 넣습니다.
- **타이틀 글자:** 두 줄 로고입니다. 위 "Cameli"는 잎 초록, 아래 "Garden"은 동백 빨강이고, 글자 크기는 200입니다.
  - 흰 테두리와 옅은 그림자가 있고, "i"의 점 자리에 작은 동백꽃이 살랑입니다(새 `StickerOutline`).
  - 카멜리, 글자, 부제, "화면을 눌러 시작"을 다시 배치해 낮은 화면에서도 겹치지 않습니다.
- **클리어 꽃잎:** 동백꽃이 다 피는 순간 목표색 꽃잎 11장이 약 3.2초 동안 흩날립니다(새 `PetalFall`, `SpriteFactory.Petal`).
  - 건너뛰어도 한 번만 떨어지고, 화면을 떠나면 바로 지워집니다.
- 기획서 9절(스플래시)과 8.1절(제작 분담), 화면 명세 4, 5, 19, 20절, CLAUDE.md에 반영했습니다.
