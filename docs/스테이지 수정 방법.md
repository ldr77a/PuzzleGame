# 스테이지 수정 방법

직접 플레이해 보고 스테이지를 고칠 때 보는 안내입니다. 코드는 몰라도 됩니다.

---

## 1. 파일 위치

스테이지 파일은 `Assets/Resources/CameliStages/` 아래 **난이도 폴더**에 있습니다. 파일 하나가 스테이지 하나입니다.

| 폴더 | 정원의 구간 | 지금 들어 있는 판 |
|---|---|---|
| `0_Tutorial` | 튜토리얼 | 1\~5번 |
| `1_Easy` | Easy | 6\~45번 |
| `2_Medium` | Medium | 46\~49번 |
| `3_Hard` | Hard | 아직 없음 |

- 게임은 이 네 폴더만 읽고, 판이 들어 있는 폴더가 곧 정원의 구간입니다. 폴더 밖(`CameliStages` 바로 아래 등)에 둔 파일은 게임에 나오지 않습니다.
- 폴더 이름을 바꾸거나 새 난이도 폴더를 만들려면 코드도 바꿔야 하니 에이전트에게 맡깁니다.
- 아무 텍스트 편집기(VS Code 등)로 열어서 고치고 저장합니다. 같은 폴더의 `.meta` 파일은 건드리지 않습니다.

예시 (`2_Medium/stage_46.json`):

```json
{
  "id": 46,
  "title": "동백꽃 문",
  "hint": "문 안의 점을 섞은 색이면 열려요. 지나가면 문이 색을 가져가요.",
  "rows": [
    "P P P B O",
    "P # g0 # P",
    "# B S B #",
    "P O O B O",
    "B P P B O"
  ],
  "target": "BP",
  "gates": ["OP"],
  "optimalMoves": 7
}
```

## 2. 항목의 뜻

| 항목 | 뜻 | 꼭 있어야 하나 |
|---|---|---|
| `id` | 스테이지 번호. 파일 이름의 번호와 같게 둡니다(`stage_46.json`이면 `46`). 번호는 폴더를 넘어 이어집니다(Easy가 45번에서 끝나면 Medium은 46번부터). 게임은 폴더 순서, 그다음 `id` 순서로 판을 놓습니다. | 예 |
| `title` | 정원과 게임 화면에 나오는 제목. 다른 판과 겹치지 않게 짧게. | 예 |
| `hint` | 판 위 말풍선 안내 문구. 새로운 것이 처음 나오는 판에만 둡니다. | 아니요 |
| `rows` | 판 모양. 맨 윗줄부터 한 줄에 하나씩, 칸은 띄어쓰기 한 칸으로 구분 (3절) | 예 |
| `target` | 목표 레시피. `"RRY"` = 빨강 2 + 노랑 1. 글자 순서는 상관없습니다. | 예 |
| `gates` | 게이트 레시피 목록. 첫 번째가 `g0`, 두 번째가 `g1`. | 게이트가 있을 때만 |
| `optimalMoves` | 가장 적은 걸음 수(★★★ 기준). **검증 메뉴가 자동으로 맞춰 줍니다.** | 예 (모르면 `0`) |
| `focus`, `swipe` | 튜토리얼용 반짝이는 칸 `[가로, 세로]`(0부터 셈)과 손가락 방향 `"up"` `"down"` `"left"` `"right"` | 아니요 |

## 3. 칸 글자

| 글자 | 뜻 | 글자 | 뜻 |
|---|---|---|---|
| `R` | 빨강 | `N` | 남색 |
| `O` | 주황 | `P` | 보라 |
| `Y` | 노랑 | `S` | 시작 칸 |
| `G` | 초록(연두) | `#` | 벽 |
| `B` | 파랑 | `g0`, `g1` | 게이트 (`gates`의 첫 번째, 두 번째) |

- 모든 줄의 칸 수가 같아야 합니다. 글자는 대문자로 씁니다.
- 레시피(`target`, `gates`)에도 같은 색 글자를 씁니다.

## 4. 스테이지가 지켜야 할 규칙

검증 메뉴가 확인하는 것:

- **풀 수 있어야** 합니다.
- **시작 칸 `S`는 가운데**입니다. 3×3·5×5는 정중앙, 4×4·6×6은 가운데 네 칸 중 왼쪽 위(위에서 둘째 줄·왼쪽에서 둘째 칸, 6×6은 셋째 줄·셋째 칸).
- **헷갈림 검사:** 그 판의 색만 써서 목표와 같은 방울 수로 만들 수 있는 다른 레시피가 목표색과 너무 비슷하면 안 됩니다(ΔE 10 이상). 게이트 레시피도 같습니다.
- **게이트는 문이어야** 합니다. 게이트 없이도 풀리거나, 최단 풀이가 게이트 너머가 아닌 시작 쪽에서 끝나면 안 됩니다.
- **난이도 폴더 안에** 있어야 합니다(1절).
- **번호(`id`)는 1부터 빠짐없이** 이어져야 하고, **난이도 폴더 순서를 따라야** 합니다. 튜토리얼 판의 번호가 가장 작고, 그다음 Easy, Medium, Hard 순입니다.
- 파일 이름이 `id`와 맞는지(`stage_NN.json`에 `"id": NN`). 다르면 문제가 아니라 "참고"로만 알려 줍니다.

검증 메뉴가 확인하지 않으니 직접 지킬 것:

- 모든 칸에 색이 있습니다. 예외는 `S`, `#`, 게이트뿐입니다.
- 한 판의 색 수: 튜토리얼(1\~5번) 2\~3색, Easy 3색, Medium 4색, Hard 5색. 노랑과 연두는 한 판에 같이 쓰지 않습니다(타일끼리 너무 비슷함).
- 목표 레시피의 방울 수: 3×3은 3\~4방울, 4×4는 3\~5방울. 클리어는 색과 **방울 수가 둘 다** 같아야 됩니다(`RB` 목표를 `RRBB`로 만들면 클리어가 아님).
- 게이트 레시피: 2가지 색, 3방울 이하.
- 바로 앞 판과 같은 3색 조합을 쓰지 않습니다. 최단 걸음은 판마다 조금씩 늘리고, 5판마다 쉬운 판을 하나 넣습니다.
- 게이트 색이 바뀌면 제목과 안내 문구의 색 이름도 고칩니다.

## 5. 고치는 순서

1. 플레이하면서 고칠 판 번호를 적어 둡니다.
2. Unity의 Play를 멈춥니다(스테이지는 Play를 시작할 때 읽습니다).
3. JSON 파일을 고치고 저장합니다.
4. Unity 창을 한 번 클릭한 뒤, 메뉴 **Cameli → 스테이지 검증**을 누릅니다.
5. 창에 "모두 통과했어요"가 나오면 Play로 확인합니다. 문제가 나오면 6절을 보고 다시 고칩니다.

`optimalMoves`가 틀렸으면 검증 메뉴가 파일의 그 숫자만 고쳐 줍니다. 다른 문제는 알려 주기만 합니다.

## 6. 검사 결과 읽는 법

창에는 요약, 고친 `optimalMoves`, 문제 목록, 참고(경고) 목록이 나옵니다. 파일 하나에 문제가 있어도 나머지 파일은 끝까지 검사합니다. Console 창에는 스테이지마다 한 줄씩 나옵니다(문제가 있는 판은 노란 경고).

```
46. 동백꽃 문  5x5 OBP 목표 BP  최단 7  목표ΔE 28.7 (BB)  게이트ΔE 45.8 (OP vs OO)  타일ΔE 55.7  무작위 0.05%  풀이 1가지  통과
```

| 항목 | 뜻 |
|---|---|
| `5x5 OBP` | 판 크기, 판에 있는 색 |
| `최단 7` | 가장 적은 걸음 수. `(저장값 9 → 고침)`이 붙으면 파일의 `optimalMoves`를 고쳤다는 뜻 |
| `목표ΔE 28.7 (BB)` | 목표와 가장 헷갈리는 다른 레시피(BB)와의 색 차이. 10보다 작으면 `!`와 함께 문제 |
| `게이트ΔE 45.8 (OP vs OO)` | 같은 검사를 게이트에 한 것. 게이트 OP와 가장 헷갈리는 것이 OO |
| `타일ΔE` | 판의 칸 색 중 가장 비슷한 두 색의 차이. 참고용, 작을수록 칸끼리 헷갈림 |
| `무작위` | 아무렇게나 걸어서 ★★ 안에 클리어할 확률. 참고용, 작을수록 생각이 필요한 판 |
| `풀이 1가지` | 최단 걸음으로 클리어하는 방법(먹는 칸 묶음)의 수. 참고용 |
| `통과` / `문제: …` | 판정 |

**ΔE**는 두 색이 사람 눈에 얼마나 달라 보이는지 나타내는 숫자입니다. 2쯤이면 겨우 구별되고, 10 이상이면 확실히 달라 보입니다.

문제 문구와 고치는 법:

| 문구 | 고치는 법 |
|---|---|
| `풀 수 없어요` | 목표 색이 판에 있는지, 벽이나 게이트가 길을 막지 않는지 확인 |
| `목표 RRO와 헷갈림 (RRR, ΔE 6.3)` | 목표 레시피나 판의 색 조합을 바꿈 |
| `게이트 OP와 헷갈림 (…)` | 게이트 레시피나 판의 색 조합을 바꿈 |
| `게이트 없이도 풀려요` | 게이트를 돌아가는 길을 벽으로 막거나, 목표 재료를 게이트 너머로 옮김 |
| `최단 풀이가 게이트 너머가 아니라 시작 쪽에서 끝나요` | 게이트가 색을 비우는 데만 쓰이는 상태. 목표 재료를 게이트 너머로 옮김 |
| `optimalMoves 줄이 없어요. …` | 파일에 `"optimalMoves": N` 줄이 없음. 알려 준 숫자로 넣고 다시 검증 |
| `optimalMoves 줄이 2개예요. …` | `optimalMoves`가 두 번 이상 적혀 있음. 하나만 남기고 다시 검증 |
| `optimalMoves가 정수가 아니에요. …` | `7.5`처럼 소수가 들어 있음. 알려 준 정수로 고침 |
| `파일을 고치지 못했어요 (…)` | 파일이 읽기 전용이거나 다른 프로그램이 잡고 있음. `optimalMoves`를 알려 준 숫자로 직접 고침 |
| `파일 인코딩이 UTF-8이 아니에요 …` | 한글이 제대로 보이는 상태에서 UTF-8로 다시 저장(VS Code: 오른쪽 아래 인코딩 표시 → "인코딩하여 저장" → UTF-8. 한글이 깨져 보이면 먼저 "인코딩하여 다시 열기" → Korean (EUC-KR)). 이때는 `optimalMoves`도 자동으로 고치지 않으니, 함께 나온 `optimalMoves를 N(으)로 직접 고쳐 주세요`대로 고침 |
| `번호(id)가 1부터 빠짐없이 이어져야 해요` | 빠지거나 겹친 번호를 고침 |
| `난이도 폴더(0_Tutorial, 1_Easy, 2_Medium, 3_Hard) 밖에 있어서 게임에 나오지 않아요` | 파일을 맞는 난이도 폴더로 옮김(8절의 옮기는 법) |
| `50번이 1_Easy에 있는데, 앞 번호인 49번이 2_Medium에 있어요. …` | 파일을 잘못된 폴더에 넣었거나 번호가 틀림. 맞는 폴더로 옮기거나 번호를 고침 |
| `JSON 형식 오류: …` | 쉼표, 따옴표, 괄호가 빠지거나 남음. 특히 마지막 항목 뒤의 쉼표 |
| `파일이 비어 있거나 JSON이 아니에요` | 파일 내용이 비었음. 다른 파일을 복사해서 다시 만듦 |
| `파일을 읽지 못했어요: …` | 파일이 열려 있지 않은지, 권한이 있는지 확인 |
| `형식 오류: …` (영어) | 아래 표 |
| `판이 너무 크거나 복잡해서 검사를 끝내지 못했어요. …` | 검사기가 끝까지 찾지 못한 판. 에이전트에게 알려 주세요 |
| `검사 중 오류: …` | 예상하지 못한 오류. 에이전트에게 알려 주세요 |

`형식 오류:` 뒤의 영어 문구(줄과 칸 번호는 0부터 셉니다. `row 2` = 셋째 줄, `(1, 2)` = 왼쪽에서 둘째·위에서 셋째 칸):

| 영어 문구 | 뜻 |
|---|---|
| `no start cell (S).` | 시작 칸 `S`가 없음 |
| `more than one start cell (S).` | 시작 칸 `S`가 둘 이상 |
| `start must be at column 2, row 2.` | 시작 칸 위치가 가운데가 아님(4절) |
| `row 2 has 4 cells, expected 5.` | 그 줄의 칸 수가 첫 줄과 다름 |
| `unknown cell token "r" at (1, 2).` | 모르는 칸 글자. 소문자도 여기에 걸림 |
| `cell (1, 2) refers to gate g1, but only 1 gate(s) are defined.` | `gates`에 그 게이트의 레시피가 없음 |
| `invalid target recipe. Unknown color letter 'r' in recipe "rry".` | 목표 레시피에 모르는 글자(소문자 `"rry"` 등). 게이트면 `invalid gate g0 recipe` |
| `invalid target recipe. Recipe is empty.` | `target`이 없거나 비었음 |
| `rows is empty.` | `rows`가 없거나 비었음 |
| `focus …`, `swipe …` | 튜토리얼용 `focus`, `swipe` 값이 판과 맞지 않음 |

참고(경고) 문구:

| 문구 | 뜻 |
|---|---|
| `파일 이름이 id와 달라요 (id: N, 맞는 이름: stage_NN.json)` | 파일 이름이나 `id` 중 틀린 쪽을 고침. 게임은 그대로 돌아갑니다 |
| `읽지 못한 파일이 N개 있어서 번호(id)가 빠짐없이 이어지는지는 검사하지 않았어요.` | 읽지 못한 파일을 고치고 다시 검증하면 번호도 검사합니다 |

`게이트를 정확한 레시피가 아닌 상태로 지나요`, `최단 풀이의 방울 수가 목표와 달라요`는 규칙상 나오지 않아야 합니다. 나오면 에이전트에게 알려 주세요.

## 7. 잠긴 스테이지까지 열어서 테스트하기

- 메뉴 **Cameli → 개발: 모든 스테이지 열기**를 누르면 체크 표시가 생기고, 정원의 모든 판을 누를 수 있습니다. 정원 화면을 다시 열면 적용됩니다.
- 저장된 진행(열린 판)은 켜기 전 그대로 남습니다. 스위치로만 열린 판을 깨도 저장된 진행은 앞으로 나가지 않으니, 끄면 직접 깨서 연 판까지만 열립니다(진행으로 열린 마지막 판을 깨면 평소처럼 다음 판이 열립니다). 끄려면 한 번 더 누릅니다.
- 별은 스위치를 켠 채 깬 판도 기록됩니다. 그래서 끈 뒤에는 잠긴 판에 별이 보이고, 정원의 별 합계에도 들어갈 수 있습니다. 깨끗하게 다시 시작하려면 플레이테스트 패널의 "다음 테스터"를 누릅니다(별, 열린 판, 힌트를 모두 지움).
- 에디터와 개발 빌드에서만 동작하고, 출시 빌드에는 영향이 없습니다. 지금은 에디터 메뉴에서만 켤 수 있습니다.

## 8. 새 스테이지 추가하기

1. 비슷한 판의 JSON 파일만 복사해서, 넣을 난이도 폴더에 다음 번호로 저장합니다(예: Medium의 마지막이 `stage_49.json`이면 `2_Medium/stage_50.json`). `id`도 같은 번호로 바꿉니다. 파일 이름의 번호와 `id`는 같아야 합니다.
   - Unity의 Project 창에서 파일을 고르고 Ctrl+D(Mac은 Cmd+D)로 복제한 뒤 이름을 바꾸거나,
   - Finder·탐색기에서 `.json`만 복사합니다. 같은 이름의 `.meta` 파일은 복사하지 마세요(두 파일이 같은 `.meta` 번호를 쓰게 됩니다).
   - 새 파일의 `.meta`는 Unity 창을 한 번 클릭하면 Unity가 만듭니다. 커밋할 때 `.json`과 새 `.meta`를 함께 넣습니다.
2. `optimalMoves`는 `0`으로 두고 검증 메뉴를 돌리면 채워집니다.
3. 번호는 1부터 빠짐없이, 난이도 폴더 순서대로 이어져야 합니다. 그래서 새 판은 **가장 뒤 폴더의 끝**에만 바로 붙일 수 있습니다. 중간이나 앞 폴더에 끼워 넣으려면 뒤의 파일 이름과 `id`를 모두 하나씩 밀어야 하니(다른 폴더의 판까지), 에이전트에게 맡기는 편이 안전합니다.
4. 정원의 구간은 파일이 들어 있는 폴더로 정해집니다.

**판을 다른 난이도로 옮기기:** Unity의 Project 창에서 파일을 다른 폴더로 끌어다 놓습니다(`.meta`도 같이 옮겨집니다). Finder·탐색기로 옮길 때는 같은 이름의 `.meta`도 함께 옮깁니다. 옮긴 뒤에도 번호가 폴더 순서를 따라야 하니, 보통 경계에 있는 판(예: Easy의 마지막 45번을 Medium으로)만 번호를 바꾸지 않고 옮길 수 있습니다.

## 9. 대신할 판 찾기를 부탁하는 법

마음에 안 드는 판은 에이전트에게 새 판을 찾아 달라고 하면 됩니다(`lab.sh search`라는 도구로 조건에 맞는 판을 자동으로 찾습니다). 아래를 알려 주면 좋습니다.

- 스테이지 번호와 마음에 안 드는 점 (너무 쉬움, 길이 하나뿐, 색이 헷갈림 등)
- 판 크기, 쓸 색 3개, 목표 레시피(또는 방울 수), 게이트 레시피
- 원하는 최단 걸음 범위, 벽 개수

예: "stage_23을 바꿔 줘. 너무 쉬워. 4×4, 색은 빨강·파랑·보라, 목표 RBB, 최단 8\~10걸음, 벽 2개로 후보 3개 보여 줘."
